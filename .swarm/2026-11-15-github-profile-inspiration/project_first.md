# Project-first profile inspiration (moiz-codez style)

Research date: 2026-11-15

## Five profiles to inspect

1. [onurdilmen/onurdilmen](https://github.com/onurdilmen/onurdilmen) — Its “Featured Work” entries use a short product summary, stack, and concrete evidence. It also includes a much longer architecture case study, which is useful to inspect for depth but probably too long to imitate wholesale.
2. [rehan243/rehan243](https://github.com/rehan243/rehan243) — Clear “Featured Projects” section with compact statements of problem, method, and technical substance.
3. [jdelaire/jdelaire](https://github.com/jdelaire/jdelaire) — A simple project list where each item gets a compact, differentiating explanation.
4. [loschenbd](https://github.com/loschenbd) — Project-first “What I’m building” list with a plain-language description on each project, plus repo pins with concise summaries.
5. [aidevforge/aidevforge](https://github.com/aidevforge/aidevforge) — Each featured project includes a name, stack, and problem/result description. It is much more verbose overall, so inspect the project-entry pattern rather than the full profile.

## Five ideas to adapt

1. **Use a four-project grid** — Viper, CAUSA, AUTOBUILD, and TrustChain each get one compact tile with a title, one-sentence description, and link.
2. **Lead with purpose, not implementation** — Say what the project is useful for first; put the technologies in a short, subdued tag row underneath.
3. **Show your contribution** — Add a brief “Designed,” “Built,” “Led,” or “Contributed” cue only where accurate, so readers understand your role.
4. **Add one proof point per tile** — A shipped state, demo, test result, scale figure, or architecture decision gives the project a concrete hook. Use only claims you can verify.
5. **Make each tile clickable and scannable** — Link the project name to its repo, and add a second “Demo” or “Case study” link only where one exists. Keep project titles, blurbs, and links aligned in a simple grid.

## Evidence and limits

Opened the live GitHub README pages for onurdilmen, rehan243, jdelaire, and loschenbd. The aidevforge profile was also inspected in search/open output. Profile content changes over time; visual rendering can differ from the text extracted by web search. These references support layout ideas, not endorsement of the accuracy of their claims.
