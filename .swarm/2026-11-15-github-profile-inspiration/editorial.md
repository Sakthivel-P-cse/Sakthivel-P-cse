# Editorial style research

## Five inspectable references

1. [Editorial Card profile template](https://github.com/beydemirfurkan/awesome-github-profile/blob/main/templates/01-minimal/editorial-card/README.md) — closest ready-to-use GitHub README example: masthead, hairline rules, short editorial copy, selected-work list, issue-style footer. It is pure Markdown with no images or external services.
2. [Readme Atelier](https://github.com/monokernn/readme-atelier) — GitHub README generator with an `Editorial minimal` style: Swiss-editorial typography, ruled headlines and serif italics. Useful to preview a more graphic version of the style.
3. [JonahFoster/astro-folio](https://github.com/JonahFoster/astro-folio) — newspaper-inspired portfolio with large masthead, dateline, bylines, column rules, numbered project columns and dispatches. This is a standalone portfolio, not a GitHub profile README.
4. [Melanie Sigrid's EditorialPortfolio](https://github.com/melaniesigrid/EditorialPortfolio) — editorial typography and a project spread organized as a series of print plates. Good reference for distinctive project presentation; this is a standalone portfolio.
5. [evanssmiles/portfolio-template](https://github.com/evanssmiles/portfolio-template) — dark editorial portfolio with a strong hero and project grid; useful if extending the profile's linked portfolio site. Standalone Next.js template, not a README design.

## Five ideas adapted to Sakthivel's profile

1. **A masthead with one clear positioning line.** Set “Sakthivel P” as the headline, with a small kicker such as `DISTRIBUTED SYSTEMS · BACKEND ENGINEERING`, and use “Building durable systems that survive failure” as the lede.
2. **A dated issue line.** Add a restrained monospace line like `ENGINEERING NOTES · CHENNAI · 2026` under a thin rule. Keep this as decoration and let the role and projects carry the actual information.
3. **Three lead project stories.** Give Viper, CAUSA and AUTOBUILD numbered entries with a short category label, one-sentence problem/outcome, stack, and repository link. Avoid a large grid of small terminal windows.
4. **A narrow “current focus” sidebar.** In a two-column rendered image or table, reserve the smaller column for current focus and core systems (Raft, CRDTs, gRPC, Temporal, Kubernetes); keep the wider column for project summaries.
5. **An issue-style footer for contact.** Close with a horizontal rule and a quiet footer such as `PORTFOLIO · LINKEDIN · EMAIL` plus an update date. Keep social links together instead of repeating them across sections.

## Source notes

GitHub's profile README documentation says profiles can show an About section and context for contributions, and profile READMEs support Markdown, images and GIFs. The concrete editorial layout examples and their details above come from the linked repositories; visual appearance can vary between GitHub light/dark themes, and the standalone portfolio references will need translating to README-supported formatting.
